title: "Performance Benchmarks"
description: Reactive V2 against V1 and BSML, in BeatLeader and in stress tests.
---

We measured BeatLeader's own UI on Reactive V1 and V2, then ran the same stress tests on V1, V2 and BSML. In BeatLeader,
UI time stayed the same while V1's memory leak is gone. In the stress tests, V2 mounts about 4× faster than V1 and lays
out faster too, and many writes in one frame cost it far less, though a single write takes a few microseconds longer.

Against BSML, Reactive is much faster when one part of a large UI changes, since only that part is laid out again, and
it usually mounts faster because it builds from code. Most rows where BSML comes out ahead are ones where it does less
of the work, as the notes under them say.

Each bar shows how many times better one side is, on a log scale. No bar means the difference is within noise. A * marks a row where the two sides don't do the same work or weren't measured the same way, with a note under its group.

## How it was measured

Everything was measured on 2026-11-05. UI time is how long the main thread spends on a frame beyond an idle one, taken
as the median (p50), while state changes are timed directly. A mount is the median of every mount after the first,
counting its first 6 frames, and memory is the managed heap while the benchmark is mounted.

The machine, the versions and the rules are listed below:

- **UI time window:** from the first `Update` to the end of `Canvas.willRenderCanvases`.
- **Same:** the ranges over all rounds overlap, or the gap is under 5% or under the noise floor of an empty benchmark, which is 0.66 ms on V1 and V2 and 1.95 ms on BSML.
- **PC:** Beat Saber 1.44.0, Ryzen 7 5800H, RTX 3070 Laptop, in FPFC on a hidden desktop, which makes absolute numbers higher than usual. V1 is Reactive `859fe5d`, V2 is Reactive `56b3941` with a Release `yoga.dll`, BSML is 1.14.1. 3 rounds of V2 and BSML, 2 of V1. BeatLeader ran 2 rounds per version, and its main menu 5 sessions.
- **Same work:** V1 and V2 end with matching layouts, apart from animations, tables and `state-subscribe`. BSML can't match them, so we compared screenshots of every benchmark instead.
- **Not covered:** PC VR, other machines and GPU cost.

### Where the work differs

Each target is written the way its library is normally used: V2 the way BeatLeader's UI is, V1 with its own API, and BSML with markup and `~value` bindings. Where that changes the work, or a target was measured differently, the chart row has a * and a note under its group.

<details>
<summary>Every difference</summary>

**V1 and V2**

- **Fresh sessions for V1:** V1's leak slows down everything after it, so its mounts, flat lists, `life-churn` and `ram-rows` each ran in a game session of their own, while V2 ran the full suite. That's V1's best case. V1's mounts on V2's Yoga also come from one session each, and its layout there from 2 rounds.
- **Callbacks:** V1 calls back on every write. That's 100000 calls per frame in `state-burst` and 262144 at the end of `state-diamond-deep`, where V2 runs each callback once per flush. So these rows show V2 doing less work by design.
- **Subscribing:** V1 has no subscription handle, so `state-subscribe` uses its C# event, which copies the whole list of callbacks on every add and remove.
- **Text:** V1 sets label text directly, and V2 writes bound states, so V2's text benchmarks include its state work.

**BSML**

- **No wrapping:** UGUI's layout groups can't wrap items of different sizes, so where one item changes size, BSML uses rows of a fixed length with the same number of items. Elsewhere a `grid` of fixed cells stands in for wrapping, so BSML's labels in `life-label` and `state-labels` aren't measured for layout, while Reactive's are, and BSML does less work there.
- **No animations:** BSML has no animation system, so a hand-written loop works out one value per frame and sets it on every item, while Reactive runs one animation per item. In `anim-position`, BSML's items also ignore layout, so only their transforms move, while Reactive's absolute flex items run layout every frame. In `ram-animated`, BSML's Images hold no animation state. In all three, BSML does less work.
- **Markup:** BSML parses markup on every mount, including all 50 rows per frame in `life-churn`. That's how BSML builds UI, so it's counted.
- **Tables:** `CustomCellListTableData.CellForIdx` creates a GameObject and parses the cell again whenever a row comes into view, instead of reusing one. That's BSML's own behavior.
- **No list component:** in `list-flat-shuffle`, each row's bound object is updated in place, while Reactive's list gets a new array of items.
- **No state system:** `state-labels` is the only state benchmark with a BSML version, and `ram-state` is left out.

</details>
