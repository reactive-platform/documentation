Typing in VR means an on-screen keyboard, so an input field is two things: the field you click, and the keyboard
modal that opens next to it. They don't reference each other. They share a `BsInputFieldContext`. The showcase's
*Input field* page:

<Playground preview="/assets/sdk/input-field.gif">
```csharp excerpt
var searchContext = new BsInputFieldContext();
var searchAnchor = Ref<RectTransform>();

new BsInputField {
    FlexItem = {
        Size = new() { x = 50.pt, y = 8.pt }
    },

    Context = searchContext,
    Placeholder = "Search songs",
    Icon = GameResources.SearchIcon,
    sInteractable = interactable,
    sColors = colors
}.Bind(searchAnchor),

new Label {
    Alignment = TextAlignmentOptions.Left,
    sText = searchContext.Map(x => x.Focused
        ? "Typing..."
        : $"Query: {(string.IsNullOrEmpty(x.Text) ? "-" : x.Text)}"
    )
},

new BsKeyboardModal {
    Context = searchContext,
    PlacementAnchor = searchAnchor,
    sShowNumbersRow = showNumbers,
    sKeyboardColors = keyboardColors
}
```
```csharp
class SearchField : ReactiveComponent {
    protected override GameObject Construct() {
        var searchContext = new BsInputFieldContext();
        var searchAnchor = Ref<RectTransform>();

        return new Layout {
            FlexController = {
                FlexDirection = FlexDirection.Column,
                AlignItems = Align.FlexStart,
                Gap = 2.pt,
                Padding = 4.pt
            },

            Children = {
                new BsInputField {
                    FlexItem = {
                        Size = new() { x = 50.pt, y = 8.pt }
                    },

                    Context = searchContext,
                    Placeholder = "Search songs",
                    Icon = GameResources.SearchIcon
                }.Bind(searchAnchor),

                new Label {
                    Alignment = TextAlignmentOptions.Left,
                    sText = searchContext.Map(x => x.Focused
                        ? "Typing..."
                        : $"Query: {(string.IsNullOrEmpty(x.Text) ? "-" : x.Text)}"
                    )
                },

                new BsKeyboardModal {
                    Context = searchContext,
                    PlacementAnchor = searchAnchor
                }
            }
        }.Use();
    }
}
```
</Playground>


The context is a [state](/docs/reactive/state/states) carrying `Text` and `Focused`. Clicking the field focuses the context,
the keyboard modal sees that and opens, keys write `Text`, and the label reads it all through `searchContext.Map`.
`PlacementAnchor` is a `Ref<RectTransform>` the field fills in with `.Bind(searchAnchor)`, so the keyboard knows
where to appear.

`Validate` on the context rejects values before they reach the field, which is how the showcase makes a PIN field
that only takes a few digits:

```csharp
var pinContext = new BsInputFieldContext {
    Validate = x => x == null || (x.Length <= MaxDigits && IsDigits(x))
};

new BsNumpadModal {
    Context = pinContext,
    PlacementAnchor = pinAnchor,
    sNumpadColors = numpadColors
}
```

`BsNumpadModal` is the numeric version of the keyboard modal, and `BsKeyboard` and `BsNumpad` are the keyboards
themselves without a modal, for when you want one embedded in a screen: `OnTextChanged`, `OnOkClicked`, and a
`Text` you set to null to clear.

Both modals are shared modals from the global pool, so one keyboard serves every input field in the mod.
## Properties

These are `BsInputField`'s. `BsKeyboardModal` and `BsNumpadModal` take the same `Context`, a `PlacementAnchor`, `PlacementData` (bottom center by default), `ShowBackground`, `Animated`, `ClickOffCloses`, and `KeyboardColors` or `NumpadColors`. The keyboard modal also has `ShowNumbersRow`. The standalone `BsKeyboard` and `BsNumpad` have `Text`, `Colors`, `OnTextChanged` and `OnOkClicked`. Every property with a setter also has an `s`-version that takes a state.
